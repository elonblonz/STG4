# STG4

This is the *Set Theory Game*. It uses the [Lean4 Game Engine](https://github.com/leanprover-community/lean4game) and it is hosted at [adam.math.hhu.de](https://adam.math.hhu.de).

Teaching with it? See [docs/instructors.md](docs/instructors.md) for learning objectives, a
mapping to *How To Prove It*, and suggested course use.

## Running the game locally

### Docker (recommended)

You only need [Docker](https://docs.docker.com/get-docker/). From the repository root:

```sh
docker compose -f .devcontainer/docker-compose.yml up
```

The first start downloads the Mathlib build cache (several GB) and builds the game, which
takes a while. Once the log shows Vite is ready, open
[localhost:3000](http://localhost:3000). Later starts reuse the cache and are fast.

Lean build outputs live in a Docker volume rather than in your checkout, which keeps builds
fast on Windows and macOS. To start from scratch, run
`docker compose -f .devcontainer/docker-compose.yml down -v`.

After changing a `.lean` file, rebuild and then reload the browser page:

```sh
docker compose -f .devcontainer/docker-compose.yml exec game bash .devcontainer/run.sh build
```

### VS Code dev container / GitHub Codespaces

Open the repository in VS Code and choose **Reopen in Container**, or create a Codespace
from the **Code** button on GitHub. This uses the same container. The game is built when the
container is created and served on port 3000 when it starts. After editing Lean files, run
`lake build` in the terminal and reload the page.

### Without Docker

You need [elan](https://github.com/leanprover/elan) (the Lean toolchain manager), Node.js
20+, and git. Clone the game engine next to this repository, at the tag that matches
`lean-toolchain`:

```sh
lake exe cache get   # download prebuilt Mathlib
lake build
git clone --depth 1 --branch "$(cut -d: -f2 lean-toolchain)" https://github.com/leanprover-community/lean4game.git ../lean4game
cd ../lean4game && npm install && npm start
```

Then open `http://localhost:3000/#/g/local/<folder>`, where `<folder>` is the name of this
repository's directory, for example `STG4`.

## Project layout

- `Game.lean` holds the game's title, intro, credits, and world dependencies, and ends with `MakeGame`.
- `Game/Metadata.lean` holds the imports and settings shared by every level.
- `Game/Levels/<World>.lean` defines one world and imports its levels.
- `Game/Levels/<World>/Lxx*.lean` holds one level each. A world's first level imports the previous world.
- `images/` holds the cover image and the diagrams. The diagrams are SVGs generated by
  `python scripts/make_diagrams.py`; edit the script rather than the SVG files. World pictures
  are attached with `Image "images/…"` in a world file. Inline diagrams are attached with
  `![alt text](images/….svg)` in level text. Keep words out of the images, since they can't be
  translated, and put explanations in the level text instead.
- `.i18n/` holds the translations. `en/Game.pot` is the English template, generated by
  `lake build`. Each `<lang>/Game.po` is a translation, and the source of truth for it.
  `<lang>/Game.json` is generated from it and loaded by the game.

## Translations

Translation keys are the English strings with each code span replaced by `§0`, `§1`, and so
on. Editing English text in a level therefore changes its key, and the old translation stops
showing. After changing English text:

```sh
lake build                          # regenerates .i18n/en/Game.pot
python scripts/i18n_merge.py        # merges it into each Game.po; lists dropped translations
lake exe i18n --export-json         # regenerates each Game.json from its Game.po
python scripts/check_i18n.py        # lints the result (CI runs this too)
```

To keep the translation of an edited string, `i18n_merge.py` takes `--rename old_new.json`
for edits that don't change the meaning. For new translations it takes `--drafts`. Run it
with `--dry-run` first to see what would change.

`check_i18n.py` reports these problems:
- mismatched `§N` placeholders, which make the game show the wrong code snippets;
- duplicate keys;
- over-escaped quotes;
- translations whose English text no longer exists.

Strings that were drafted without native-speaker review are listed in
`.i18n/TRANSLATIONS_TODO.md`.

## Running against a lean4game fork

The game's UI comes from the [lean4game](https://github.com/leanprover-community/lean4game)
engine, not from this repository. The Docker image applies our engine changes on top of
upstream from `.devcontainer/lean4game-patches/0001-stg4-engine.patch` (dark mode, the
phone and tablet layout, the visual refresh, and fixes to level navigation and submitting
commands; the patch's header lists the commits). To work on the engine itself, point the
Docker build at your fork:

```sh
LEAN4GAME_REPO=https://github.com/<you>/lean4game.git LEAN4GAME_REF=<branch> \
  docker compose -f .devcontainer/docker-compose.yml build
```

To use a local checkout of the engine's Lean server instead of the published one, run
`lake update -R -Klean4game.local`. It expects the checkout at `../lean4game` (see
`lakefile.lean`).

## Deploying

Pushing to `main` builds the game and uploads it as a workflow artifact. To publish it to
[adam.math.hhu.de](https://adam.math.hhu.de), open
`https://adam.math.hhu.de/import/trigger/<owner>/<repo>`.

If you host the patched engine yourself, replace the placeholder impressum and privacy
policy in the engine's `client/public/legal/` (`impressum.md`, `privacy.md`) with your own.
